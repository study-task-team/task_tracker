# Стратегия ветвления

Мы используем **GitHub Flow**.

## Правила
- Основная ветка: `main` (всегда рабочая, защищена от прямых пушей).
- Для каждой задачи создается ветка от `main`: `feature/<issue-id>-<short-name>`.
- Слияние в `main` только через Pull Request.
- Слияние выполняется методом **Squash and merge** (один PR = один коммит в истории).
- После слияния ветка задачи удаляется.
