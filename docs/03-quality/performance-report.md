# Отчёт о производительности

## Замер «До» (Baseline)

**Сценарий:** 10 пользователей, 30 секунд.
**Инструмент:** Locust.

| Метрика | Значение |
|---|---|
| Общее количество запросов | 200 |
| RPS (средний) | ~6.6 |
| Avg response time (среднее) | 11 мс |
| Max response time (максимум) | 74 мс (POST /login) |
| 99-й процентиль | 69 мс |

**Выявленное узкое место:** Операции записи в БД (POST /login, POST /courses) занимают в 2 раза больше времени, чем чтение (GET). SQLite блокирует базу на время записи.
## Замер «После» (Оптимизация WAL)

**Что сделали:** В `src/db.py` добавлен режим WAL (Write-Ahead Logging) для SQLite.
**Результат:** Чтение перестало блокироваться при записи.

| Метрика | До | После | Изменение |
|---|---|---|---|
| POST /courses (Avg) | 18 мс | 14 мс | -22% |
| GET /courses (99%) | 43 мс | 16 мс | -63% |
| Общий 99% | 69 мс | 29 мс | -58% |

**Вывод:** Включение WAL-режима ускорило чтение в 2.6 раза и снизило общий 99-й процентиль в 2.3 раза. Узкое место (блокировка базы данных) устранено.
